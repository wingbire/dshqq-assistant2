## 一、已通过项（含实测证据）

### ✅ M0-1 独立 DSH_HOME
```
$env:DSH_HOME=".m0\\dsh-home"
dsh qq --from-default-profile web --dump-config   →  正常输出完整插件树
```
隔离 home 内自动生成 `profiles/qq`（bundles: `dsh-base` + `dsh-web-app`）。
**不需要复制主 home 那 315 MB 插件依赖，也不需要 pnpm install。**

### ✅ M0-2 独立 API Key 注入（关键）
DSH 报错信息直接给出了两条官方途径。实测采用环境变量：

| 测试 | 结果 |
|---|---|
| 不设 Key | `MISSING_CREDENTIAL: no API key for provider route "deepseek-official"` |
| 设假 Key | `AUTH: api key ****0000 is invalid` ← 证明变量被读取 |
| 设真 Key | **回答「可以」，耗时 2337 ms** |

**结论：程序 spawn 专用 DSH 时只需设 `DEEPSEEK_API_KEY` 环境变量，完全不用碰凭据文件格式**——零损坏风险。

### ✅ M0-3/M0-4 双实例共存 + 凭据隔离
```
127.0.0.1:19387  pid=12472  主 DSH 桌面版（你的）
127.0.0.1:19388  pid=9756   专用 qq 实例（隔离 home）
```
两者同时运行无冲突。隔离 home 的 `.credentials.yaml` 里**只有 browser-session，没有 DEEPSEEK_API_KEY**，证明**不会串用你的主 Key**。会话落盘为 `session.v4.jsonl.zstd`，与你主 DSH 完全分开。

### ✅ M0-8 csc 托盘启动器
```
csc /target:winexe /resource:payload.txt,payload.txt ...
→ tray-result.txt: resources=payload.txt;payload=EMBEDDED-PAYLOAD-OK;trayCreated=true;exited=true;
```
5.6 KB exe，内嵌资源解出正常、托盘图标创建成功、可干净退出。**单 exe 形态确定可行，Node SEA 风险清零。**

## 二、❌ M0-5：C 档主链路不成立（需要改方案）

### 实测
- 常驻实例能起（19388），`?token=` 能换到 `dsh-auth-*` HttpOnly Cookie，请求从 401 变 404 → **鉴权可绕过**
- 但**找不到可用的公开受控接口**：633 KB 前端包里搜不到任何 `/api/` 业务路径，也没有 WebSocket/SSE 客户端；接口由 `@deepseek-ai/dsh-api-gateway` 在运行时装配

### 判断
C 档要成立，就得**逆向 DSH 的内部 RPC 协议**——一个每次 DSH 升级都可能变、且没有任何兼容承诺的私有接口。这是把整个机器人押在最脆弱的一环上。

### 对比 B 档（实测）
```
dsh headless --session-id <群会话> "消息"    →  全流程 2337 ms（含冷启动+推理）
```
**B 档拿到了 C 档的全部目标**：常驻会话记忆、人设、技能、工具。唯一差别是每条消息多约 1 秒进程启动——群聊场景完全可接受。

### 建议
**默认改为 B 档**（`--session-id` 分群会话），C 档降级为面板里"可选的常驻实例"，仅供你人工查看，不作为机器人主链路。
