# DSH-QQ 群小助手 · 设计方案 v3（已批准执行）

> v2 → v3 变更：NapCat 改为**对接模式**（不自管 QQ 账号/托盘/安装/更新）；大脑**默认 B 档**（C 档保留为可选）；自研代码许可 **MIT**。范围收敛，里程碑重排。

---

## 1. 最终范围

### 我们做（独有价值）
1. **DSH 接入**：把"你"接进 QQ 群（独立 DSH_HOME、专用 qq profile、环境变量注入 API Key）
2. **省 token 闸门**：十项机制，管理动作与回复判定全部本地完成（0 token）
3. **群管理引擎**：违禁词阶梯处置、广告/刷屏拦截、欢迎、关键词回复、@全体限流、管理员指令、审计日志
4. **人设三层编辑器**：全局 / 群级覆盖 / 临时指令，含字数与成本预估、版本回滚
5. **统一面板 + 用量看板**

### 我们不做（交给 NapCatQQ-Desktop）
- QQ 账号登录与切换、实例启停与守护、NapCat/QQ 安装与更新、托盘托管
- 原因：官方 `NapNeko/NapCatQQ-Desktop`（Rust / GPL-3.0 / 活跃维护）在这些方面更成熟；且我们不对接其内部实现，只连 OneBot WS，因此自研代码可保持 **MIT**

### 对接方式
我们作为 **OneBot 11 正向 WebSocket 客户端** 连接 NapCat（默认 `ws://127.0.0.1:3001`，带 token）。
面板用 `get_login_info` 显示当前接入的 QQ 号，并展示群列表。账号切换在 NapCatQQ-Desktop 里完成，我们自动跟随。

## 2. 大脑：默认 B 档，C 档可选

| | **B 档（默认）** | **C 档（可选）** |
|---|---|---|
| 调用方式 | `dsh headless --session-id <群会话>` 按需调用 | 常驻 `dsh web` 实例 + 内部接口 |
| 记忆 / 人设 | 完整 | 完整（同一份存储） |
| 延迟 | 实测 2337ms（含冷启动） | 略快约 1 秒 |
| 接口 | 官方文档化 CLI | 未公开内部 RPC |
| 稳定性 | 高 | 低（DSH 升级可能失效） |

两者共用同一 `DSH_HOME`，因此 C 档**随时可加，记忆无缝延续**。

## 3. 数据布局

~~~
<程序所在目录>\dsh-data\\
├─ config\\app.json        程序设置（OneBot 地址、档位、闸门、名单）
├─ config\\secrets.json    专用 API Key（M4 起用 DPAPI 加密）
├─ dsh-home\\             专用 DSH（凭据/会话/用量，与主 DSH 完全隔离）
│   └─ profiles\\qq\\     专用 profile（人设、模型、reasoningEffort 覆盖）
├─ persona\\              人设三层 + 版本历史
├─ data\\groups\\         群档案（长期记忆）、规则、审计日志
└─ logs\\
~~~

启动专用 DSH 时注入环境变量：
~~~
DSH_HOME        = <数据目录>\\dsh-home
DEEPSEEK_API_KEY= <程序里的专用 Key>
~~~

## 4. 交付形态

**单 exe = C# WinForms 托盘启动器 + 内嵌（node.exe + 应用代码）**
- 托盘菜单：打开面板 / 启动 / 停止 / 状态 / 退出
- 首次运行自解压到 `<程序所在目录>\dsh-data`
- 已实测：csc 编译、内嵌资源、托盘创建、干净退出全部通过（M0-8）
- 约 100 MB；无开机自启（按你要求）

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 小号被封（第三方协议端固有） | 保守模式：回复限频、禁止主动加好友/邀请/批量操作 |
| NapCat 与我们的连接中断 | 自动重连 + 面板告警；连接异常不影响配置数据 |
| 人设改动导致缓存前缀失效 | 面板提示 + 避免频繁大改 |
| 群聊噪音污染记忆 | 每群生成"群档案"由 DSH 定期提炼，不依赖原始会话 |
| 工具能力被群友利用 | B 档严格白名单 + 显式指令触发 |
| DSH 版本升级 | 启动检测版本并告警；B 档走官方 CLI，兼容风险低 |"}]
