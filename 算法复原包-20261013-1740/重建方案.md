## 二、判定链路（数据流，逐步）

```
QQ 事件(NapCat/OneBot v11)
  └→ 归一化：外部文本一律过 untrusted.oneLine(群昵称/头衔)
      └→ ① 硬触发检测：@我 / 回复我 / 叫外号  →  gate 系数(Low/High) 抬底座
          └→ ② 对象判断 p_say：addressee.judge() → conf
              ├─ conf < 0.75：灰区复核（问一次模型，IGNORE 则静音；在 fork 之前生效）
              └─ conf ≥ 0.75：继续
                  └→ ③ 语义 v_sem：classify → 话题桶 + 话题深度 TOPIC_DEPTH_K
                      └→ ④ 对话延续 v_cont：被直接回复/刚说完/群里在聊我/全新话题
                          └→ ⑤ 需求 v_demand：demandScore 归一化
                              └→ ⑥ 成本：d_diff(问题类型+是否要长内容+历史输出规模) × d_cost(未命中输入+2×输出)
                                  └→ U = (w1·p_say + w2·v_sem + w3·v_cont + w4·v_demand) − λ_eff·(d_diff·d_cost/costScale)
                                      └→ 档位：U<speakAt 不说 / speakAt~terseAt 极短 / terseAt~detailedAt 常规 / >detailedAt 多讲两句
                                          └→ 话风臂：bandit 按 (话题桶 × arm) 采后验取最大 → terse/standard/detailed
                                              └→ 生成 → 发送
                                                  └→ 反馈：engagement(+4 接着聊并叫外号 / +2 接着说 / −1 没人接 / −2 嫌烦)
                                                      └→ reward = engagement − λ·norm
                                                          └→ 在线更新：addressee IDF/权重 · bandit 后验 · profile PARAM_BOUNDS
```

## 9.1 判定链路（替换 §二 的灰区部分）

```
事件 → 外部文本归一化 → 硬触发(@我/回复我/叫外号 → gate 底座；@ 命中则直接回复)
   → 本地评分（五特征族：语义分割 / 消息间联系 / 连续性 / 指向性判别 / 昵称头衔×历史）
       └→ p_say（是不是在对我说）
   → 阀门判决（自适应灰区边界）
       ├ 否  → 直接不回复；**不经过大脑**
       ├ 是  → 进大脑
       └ 灰区 →  综合判断 **回复深度**，按三档分流：
             ├ 深度不高 → **不进大脑**，本地短句回应
             ├ 深度中   → 不搜索 或 只搜一次 → 总结回答
             └ 深度高   → 搜索一次 + **外审一次（其它模型，返回 是/否/不确定）** → 详细回答
   → 三档各有**加权后的字数限制**
   → 成本记账：**单次确定的回复所花费的 token**
   → 反馈：小助手对某人回复后，看**那个人**是接着跟小助手聊（+）还是转去跟别人聊（−）
       └→ reward = engagement − λ·norm → 在线更新
   → 每累计 **20 次回复**（`refN: 20`）→ 历史消息发大脑 → **提炼群档案** + **动态调整群专属关键词**
```

## 9.2 新增/强化的参数

| 参数 | 值/含义 | 来源 |
|---|---|---|
| `refN` | **每 20 次回复做一次群档案提炼** | `score.js`（默认 20）× 口述 |
| 灰区边界 | **自适应调节**（非固定） | 口述（需补调节算法） |
| 外审返回 | **是 / 否 / 不确定**，用**其它模型** | 口述 |
| 成本口径 | **单次回复的总 token**（含复核与大脑） | 口述 × `d_cost` |
| 群专属关键词 | **大脑每 20 次回复动态调整**（喂给 TOPIC_DEPTH_K 的话题词表） | 口述 × `utility.js` |

## 9.4 验收标准的增补

- **深度分档回归**：同一批消息在"深度不高/中/高"三种输入下，应分别表现为「本地短句 / 不搜或搜一次 / 搜一次+外审一次」，且字数落在各自限制内。
- **接话归因**：必须能区分"被回复人继续跟小助手聊"与"转去跟别人聊"两种结果，并分别计入正/负反馈。
- **学习节奏**：第 20 次回复后应发生一次群档案提炼与关键词调整（可观测：档案文件 mtime / 关键词快照变化）。
