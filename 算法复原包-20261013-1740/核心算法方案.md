## 0. 目标：最终要看到的表现（验收锚点）

| 期望表现 | 由哪个环节负责 | 怎么观测 |
|---|---|---|
| 有**独特性格** | 全局人设 prompt + 每群群档案 prompt（大脑输出前的 prompt 前缀） | 同一句话在不同群语气不同；群档案文件存在且非空 |
| **自动管理群聊** | commands（指令模块）+ triggers（节流/预算） | 管理指令可执行；刷屏时有冷却 |
| **时不时主动搭话** | proactive（兴趣命中 + 概率 + 节流） | 无 @ 也能在感兴趣话题上插话，且频次可控 |
| **判断该不该回** | 本地评分五特征族 → 阀门三态（否/是/灰） | 无关闲话不接；被点名必回（硬触发地板） |
| **该认真回还是简单回** | 深度三档：20 / 60 / 200+ | 三种输入下回复长度落档；越档有处理 |
| **要不要先上网搜** | 深度档 → 搜索决策（0 或 1 次 + 关键词） | 简单档不触发搜索；认真档触发且带关键词 |
| **有活人感** | 人设 prompt（口语、情绪起伏、会长会短、偶尔吐槽） | 人工盲评：像人不像机器人 |
| **配表情包辅助情绪** | meme-send（情绪 → 图库检索 → 发送） | 带情绪的回复后跟图；不滥用 |

一句话验收：**给定 30 条群聊消息（含点名 / 闲聊 / 提问 / 梗 / 无关），系统的"说不说 / 说多长 / 搜不搜 / 配不配图"四项决策，人工判定一致率达标。**

## 2. 判定链路（逐步施工说明）

### 2.1 归一化（每个事件进来先做的三件事）

1. **外部文本原语**：群昵称、群头衔、转发内容一律走 untrusted 的 oneLine —— 去换行、限长、去控制符、打「不可信」标记（**防注入**）。
2. **事件整形**：OneBot v11 的 message 事件 → 内部事件 {gid, uid, text, atBot, replyToBot, replyToOther, ts}。
3. **硬触发检测**：@我 / 回复我 / 叫外号 命中 → 抬高 gate 系数（地板），不允许「被点名也不回」。

### 2.2 五特征族 → 本地评分（p_say：这句话是不是在对我说话）

| 特征族 | 实现 | 说明 |
|---|---|---|
| A 语义分割 | classify：分类（提问 / 梗与吐槽 / 游戏机制 / 日常闲聊 / 其他）+ 话题深度 | 两种路线见 §3.3，二选一 |
| B 消息间联系 | addressee 的每群 IDF 语料 + ngram（中文 N 元 + 拉丁词） | 在线学习：群里每句话都喂进来 |
| C 连续性 | v_cont 状态机：被直接回复 / 我刚说完 / 群里在聊我的话题 / 全新话题 | 用最近若干条消息的位置关系算 |
| D 指向性判别 | ① 外号 / 昵称是否指向小助手；② 多个人称代词同现时，句意是**陈述性**还是**指向性** | **只在没 @ 时才需要**（@ 直接回） |
| E 昵称头衔 × 历史 | perUser 统计（谁常接我、谁叫我外号、谁在跟我说话） | 与 D 共用同一套实体表 |

输出：p_say（置信度）+ 归因信号（jr.signals：每个特征为什么加分/扣分）。
已知的字面扣分特征：negationToMe（否定我）、reporting（转述）、thirdPersonDense（第三人称密集）、evaluative（评价调侃）。

### 2.3 阀门与自适应灰区

判决三态：**否 / 是 / 灰**。

- 边界 = 灰区的**上下限**，**自适应调节**（调节算法待定，见 §7）
- 已知一个参照值：**conf < 0.75** 落灰区（[实测][口述]）
- 硬触发命中时，即使判否也至少给一句短的（gate 地板）

### 2.4 三态各走哪条路

| 判定 | 动作 | 成本 |
|---|---|---|
| 否 | **直接不回，不进大脑** | 只花本地算力 |
| 是 | 进大脑生成 | 大脑 token |
| 灰 | 交给**深度分档**决定（见 2.5）；必要时外审一次 | 外审 + 可能的大脑 token |

### 2.5 深度分档与搜索决策（灰区/是 之后的核心）

用一个与 p_say 同构的评分算**回复深度**，落到三档：

| 档 | 行为 | 字数限制 |
|---|---|---|
| 不高 | **不进大脑**，本地短句回应 | **20** |
| 中 | 不搜索 或 只搜一次 → 总结回答 | **60** |
| 高 | 搜索一次 + 外审一次 → 详细回答 | **200+** |

- 三档**各有加权后的字数限制**；达到限制时，由**全局人设 prompt** 决定是「拆两条」还是「压缩成一条」（实现为开关 splitOnOverflow）
- **搜索决策**：是否搜 / 搜几次 / 用什么关键词 —— 由深度分档给出（关键词可由大脑或本地规则生成）

### 2.6 外审（其它模型）

- 触发：深度高（或灰区需要复核）
- 调用**其它模型**（不是同模型换 prompt）
- 返回**是 / 否 / 不确定**
- 「不确定」的处置：**与本地三态联合**再调深度
  - 本地否 + 外审不确定 → 下调（更浅 / 不回）
  - 本地不确定（灰） + 外审不确定 → 按深度评分定档

### 2.7 成本与综合效用

成本口径：**单次确定的回复所花费的 token**（含搜索与外审的消耗）。
[实测] utility 里的成本项：cost = λ · d_diff · (d_cost / costScale)，d_cost = 未命中输入 + 2×输出

综合效用（六因子）：

    U = (w1·p_say + w2·v_sem + w3·v_cont + w4·v_demand) − λ_eff · (d_diff · d_cost / costScale)

[实测] 权重与阈值：w1 0.40 / w2 0.20 / w3 0.25 / w4 0.15；λ 0.5；gateLow 0.15 / gateHigh 0.5；TOPIC_DEPTH_K 0.10
[实测] benefit 实际写法：benefit = (w1*pSay + gate*(w2*clamp01(sem) + w3*cont + w4*clamp01(demand))) * eng

### 2.8 生成与输出整形（进大脑之后）

1. 组装 prompt：**全局人设 prompt** + **本群群档案 prompt** + 最近上下文 + 本轮任务（仅短评 / 总结 / 详细）
2. 大脑生成
3. 输出整形：字数限制 → 超限按 splitOnOverflow 处理；情绪 → 决定是否配表情包
4. 表情包：命中情绪时由 meme-send 从图库检索并发送（契约见 §3.6）

### 2.9 反馈与自学习

- **反馈定义（关键）**：小助手对**某个人**回复一次后，看**那个人**是继续跟小助手聊（正）还是转去跟别人聊（负）
- [实测] engagement 档位：+4 接着聊并叫外号 / +2 接着说 / −1 没人接 / −2 嫌烦
- [实测] reward = engagement − λ · norm（score.js 默认 λ 1.0、alpha 0.25、beta 0.8、**refN 20**）
- 学习目标：① addressee 的 IDF/权重 ② bandit 的话风臂后验（Thompson：terse / standard / detailed × 话题桶） ③ profile 的按群参数（PARAM_BOUNDS 内）
- **节奏**：每累计 **20 次回复**（refN）→ 历史消息发大脑 → 重炼群档案 + 动态调整群专属关键词

### 2.10 群档案（每群一段 prompt）

- 每群一份，内容为**群友性格 / 兴趣 / 雷点（禁忌）**这类画像
- 形态是**大脑输出前的 prompt 前缀**（不是数据库 schema）
- 由大脑每 20 次回复重炼一次

### 2.11 主动搭话（proactive）

- 触发：扫描到的消息**命中本群兴趣**（来自群档案关键词）且未被阀门判否
- 约束：概率（group.rate 0.15~0.6）+ 冷却 + 每群预算（triggers 模块）
- 输出：通常走**低档**（≤20 字）短评，必要时升档

### 2.12 人工标注与校准（labels）

- 管理员在配置端手动判定「这条消息该不该回」
- 用途是**双目标校准**：校准本地权重（p_say 的准确度）与**外审阈值**（灰区判据的准确度）
- 建议字段：{msgId, gid, uid, text 摘要, 人工判定(该回/不该回), 当时本地判定, 当时外审结果, 标注人, 时间}

### 3.2 untrusted（零证据 → 建议原语清单）

    oneLine(text, maxLen) → string   去换行/去控制符/截断/标不可信
    stripQuote(text) → string        转发内容里的嵌套引用一律剥掉

    isInstructionLike(text) → bool   疑似注入（要我做…/忽略上面…）→ 打标，不执行

### 3.3 classify（仅 17 行片段 → 两条路线二选一）

    classify(text, ctx) → { buckets: string[], topicDepth: 0|1|2|3, keywords: string[] }
    路线 A（本地、零成本、可解释）：关键词表 + 规则打分
    路线 B（本地小模型 / API）：语句分类模型
    建议：默认 A（先用规则跑通），B 作为可替换实现挂在同一签名下

### 3.4 gatescore（零证据 → 职责待你确认）

方案甲（推荐）：gatescore = **深度分档器**（把深度评分映射到 20 / 60 / 200+ 三档 + 是否搜索 + 搜几次）
方案乙：gatescore = **阀门与灰区判决器**（把 p_say 映射到 否/是/灰）

    scoreDepth(signals, cfg, state) → { depth: "low"|"mid"|"high", search: 0|1, keywords: string[] }
    judge(valve, pSay, cfg, state) → { verdict: "no"|"yes"|"grey", bounds: {lo, hi} }

### 3.5 gates.decide（入口，仅 10 行片段 → 按此重写）

    decide(evt, cfg, state, opts) → {
      action: "ignore" | "local_short" | "brain",
      depth: "low"|"mid"|"high",
      search: 0|1, keywords: string[],
      audit: "none"|"called"|"yes"|"no"|"unsure",
      score: { U, pSay, sem, cont, demand, diff, cost, gate },
      reason: string[]        // 归因，便于标注与调试
    }

分支顺序（硬触发优先，避免「被点名不回」）：

    1 归一化 + 硬触发检测
    2 本地评分（五特征族 → p_say）
    3 阀门判决：否 → ignore（硬触发命中则降级为 local_short）
               是 → 深度分档
               灰 → 深度分档 + 必要时外审
    4 深度不高 → local_short（不进大脑）
      深度中   → brain（search 0 或 1）
      深度高   → 外审 → brain（search 1）
    5 成本记账 + 埋点（供反馈与标注用）

### 3.6 meme-send 契约（表情包）

    触发：生成结果的情绪标记
    约定：大脑在文本里输出标记 [表情: 情绪或描述]；发送器解析后用该描述去图库检索并发送
    规则：只在情绪明确时用；连发不超过 1 张；正经回答（高深度/管理指令）不配图

### 3.7 外审契约

    audit(text, ctx, cfg) → { verdict: "yes"|"no"|"unsure", model, tokens }
    要求：用**其它模型**；返回三值；把结果记入反馈与标注

### 3.8 存储契约（store 已取回 305 行）

    json 文件：rules.json（群规）/ cache / 群档案（每群一份 prompt）
               interaction-feedback.json（互动事件）
               addressee-weights.json（对象判断权重）
               bandit 状态（按桶×臂的后验）
               labels（人工标注）
    键位：按 gid 分片；每份都有上限（防无限增长）

## 5. 验收标准

**行为级（8 项）**：见 §0 的表，逐项给观测方式。
**回归级**：
1. 判定用例集（自建 30~60 条）：「@我 / 直接问『你』但没 @ / 第三人称 / 转述 / 否定我 / 评价调侃 / 被点名必须回 / 全新话题不插嘴」→ 与人工标注一致，改动可追踪翻转
2. 深度分档：同批消息在三种输入下分别表现为「本地短句 / 不搜或搜一次 / 搜一次 + 外审一次」，字数落档
3. 单调性（代价感知）：λ 调大 → 回复率与平均长度单调下降
4. 学习节奏：第 20 次回复后应发生一次群档案重炼（可观测文件 mtime / 关键词快照变化）
5. 表情包节制：高深度与管理指令的回复不配图；连发不超过 1 张
